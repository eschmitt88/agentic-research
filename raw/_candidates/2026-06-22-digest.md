## Skill-library lifecycle & harness evolution

1. **SkillComposer: Learning to Evolve Agent Skills for Specification and Generalization** — method
   - https://arxiv.org/abs/2606.06079 · arXiv v1 Jun 4 2026
   - Three learnable operations — **create, improve, merge** — let an agent
     refine its skill set at inference time, addressing the tension between
     task-specific skill utility and cross-task transferability. Offline /
     Online / Hybrid deployment modes (build a generalized library vs.
     specialize per task). Reports gains on agent + code tasks while keeping
     generalization to unseen domains. No code URL surfaced.
   - reason: a clean fresh attestation for `skill-library-lifecycle` and
     `evolutionary-expansion` — the create/improve/merge triple is exactly the
     library-time curation loop (cf. SkillOps task-time/library-time split,
     cho2026skillret, ouyang2026skillos). The specification-vs-generalization
     framing also touches `shared-skill-namespace`. Top ingest candidate.

2. **Bayesian-Agent: Posterior-Guided Skill Evolution for LLM Agent Harnesses** — method
   - https://arxiv.org/abs/2606.08348 · arXiv v1 Jun 6 2026 · code: github.com/DataArcTech/Bayesian-Agent
   - Treats agent skills as statistical hypotheses, maintaining posterior
     success/failure estimates and evolving the skill library by Bayesian
     update rather than ad-hoc edits. Reports 15–20 pp gains across multiple
     benchmarks.
   - reason: pairs naturally with SkillComposer on the skill-evolution front,
     but the Bayesian posterior as the **fitness signal** also maps to
     `programmable-evaluator-oracle` and `pass-at-k` (variance-aware skill
     selection). Has runnable code — strong second ingest.

## Agent memory evolution & retrieval

3. **EvoArena: Tracking Memory Evolution for Robust LLM Agents in Dynamic Environments** — benchmark + method
   - https://arxiv.org/abs/2606.13681 · arXiv v1 Jun 11 2026
   - Benchmark for LLM agents in **progressively changing** environments
     (terminal, software, social); current agents average only 39.6% accuracy.
     Proposed method **EvoMem** tracks environmental evolution via structured
     update histories, with consistent gains on EvoArena plus GAIA (+6.1%) and
     LoCoMo (+4.8%). No code URL surfaced.
   - reason: the freshest in-window item and squarely on the memory front —
     `agent-native-memory` + `selective-memory-retrieval` (structured update
     histories as the retrieval substrate) and `structured-world-model`
     (tracking environment change over time). Top memory-cluster ingest.

4. **EvolveMem: Self-Evolving Memory Architecture via AutoResearch for LLM Agents** — method
   - https://arxiv.org/abs/2605.13941 · arXiv v1 May 13 2026 · code: github.com/aiming-lab/SimpleMem
   - Co-evolves **the stored knowledge and the retrieval mechanism together**
     via an LLM-powered diagnosis module that discovers effective retrieval
     strategies; evolved configurations transfer positively across tasks.
   - reason: directly attests `selective-memory-retrieval` (retrieval policy as
     a learned/evolved object, not a fixed heuristic) and `agent-native-memory`;
     the "AutoResearch over your own memory config" loop is a memory-flavored
     `evolutionary-expansion`. Pre-window (mid-May) and not in the graph; has
     code. Queue for ingest or `/curate`.

## Context / working-set policy

5. **Less Context, Better Agents: Efficient Context Engineering for Long-Horizon Tool-Using LLM Agents** — empirical study
   - https://arxiv.org/abs/2606.10209 · arXiv v1 Jun 8 2026
   - Compares four context-management strategies on long-horizon tool-use;
     "**prune to the last 5 tool calls** + automated summarization" reaches
     91.6% task completion while sharply cutting tokens and wall-clock vs.
     full-history retention. Enterprise expense-itemization domain.
   - reason: concrete, measured attestation for `context-eviction-policy` and
     `scripted-tool-pipelines` — a specific eviction heuristic (last-K tool
     calls + summary) with a token/quality tradeoff curve. Domain is enterprise
     rather than research-agent, so relevance is architectural-by-analogy;
     defer behind the four above, ingest or `/curate` if headroom allows.
