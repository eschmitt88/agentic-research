## Method note

Followed the retrieval recommendation the 08-31 digest recorded: the
arXiv API with an explicit `submittedDate:[202608310700 TO 202609072359]`
range is authoritative on date and needs no per-item verification, where
scenario-form `WebSearch` returns overwhelmingly pre-window results for a
7-day window (sub-week-old papers have almost no indexed web presence).

Both paths were run this week to test that claim again, and it held:
five scenario `WebSearch` queries across the active fronts returned ~60
distinct papers of which **3** were in-window; four arXiv API sweeps
returned ~150 in-window papers. The scenario queries were not wasted —
they supplied the framing that ranked the API output, and they caught
`2609.00065` (v1 30 Aug, v2 2 Sep), which a strict `submittedDate` range
on v1 would have missed. Recommended default stands: **API for the
recency filter, scenario WebSearch for framing and non-arXiv sources.**

Announcement lag note: no results exist for 09-05..09-07 (weekend +
arXiv announcement schedule); the effective window closes 09-04. Four
sweeps were needed because `max_results` caps at 60 and the 09-02..09-04
volume saturated the first page of the first two.

## Enforcement-boundary placement

**1. Where Reliability Lives: Experimental Localisation of Behavioural
Properties in an Agent System** — arXiv:2609.03192 (2026-09-02),
Marsden, Collecutt & Marsden. `paper`
<https://arxiv.org/abs/2609.03192>
The strongest placement-axis item to date, and the first that treats
placement as an *experimental* question rather than a design assertion.
Randomised interventions on a simulated settlement with an append-only
ledger, ablating either the institution's epistemic mechanisms or the
agents' cognition while holding the other constant. Five properties —
singular accepted reality, typed refusals of invalid acts, duty
persistence, single-work acceptance, zero false completions (2,581
cases) — survive cognitive ablation, LLM substitution and injected false
testimony, localising them to the institution; belief formation and
trust calibration localise to cognition (one falsehood cost trusting
runs ~900 futile actions). Preregistered predictions.
*Why:* `enforcement-boundary-placement` asserts enforcement cannot live
in the model; this measures that claim per-property instead of assuming
it, and the typed-refusal result also lands on `typed-enforcement` and
`refusal-cost-symmetry`.

**2. CONTINUITY: Security-Context Contracts for Composable LLM Agent
Controls** — arXiv:2609.05269 (2026-09-04), Zheng & Yang. `paper`
<https://arxiv.org/abs/2609.05269>
Security context is "dropped, widened, rebound, or reinterpreted as
actions cross component boundaries". Assume-guarantee contracts plus
authenticated contexts; every realised external effect must carry an
authorisation witness binding principal, task, provenance, delegation,
policy state, action and finality boundary. 0 harmful effects across
2,560 attack instances.
*Why:* argues the boundary is **distributed across every component
interface** rather than at one chokepoint — a distinct answer from all
seven sources currently on the concept, which each name a single site.

**3. ACLE-MCP: Attested Capability Leases for Execution-Time Trust in
Remote LLM Tool Use** — arXiv:2609.02690 (2026-09-02), Ding, Luo, Chen,
Shen & Wu. `paper` <https://arxiv.org/abs/2609.02690>
Short-lived sender-constrained capability leases binding expected
workload state and parameters; the execution gate sits **provider-side,
immediately before protected tool logic**, not at connection or
delegation time. Blocks post-authorisation attacks; ~26% latency over
OAuth-only.
*Why:* a sixth distinct placement (execution-time, resource-side) plus a
measured cost for it — `permission-gate-as-architecture` has no
overhead number attached to any of its 24 sources.

**4. SoK: When Safe Agents Fail Together: The Security of Multi-Agent
LLM Systems** — arXiv:2609.00595 (2026-09-01), Yang, Xu, Liu, Fendley,
Hong, Li & Cao. `paper` <https://arxiv.org/abs/2609.00595>
197 works systematised, 44 evaluation/benchmark studies audited.
A-I-R framing: 4 adversary positions × 6 interaction interfaces × 7
system-level risks, 8 recurring attack paths, defences as a five-part
contract (path target, observation, intervention, trust boundary,
recovery).
*Why:* the core thesis — safeguards that hold per-agent fail when
information and authority cross principal boundaries — is the
placement question restated at the multi-agent scale, and the
benchmark audit is a second front on `hce-evaluation`.

**5. SafeEvolve: Harness-Policy Co-Evolution from Agent Experience for
Safety Alignment** — arXiv:2609.02786 (2026-09-02). `paper`
<https://arxiv.org/abs/2609.02786>
Places the evolving constraint in the **harness** and co-evolves it with
the policy from accumulated agent experience.
*Why:* sits on the seam between `enforcement-boundary-placement` and
`skill-library-lifecycle` — the boundary is not just placed but
*learned into* the artifact that holds it.

## Evaluation integrity / evidence-gated completion

**6. TruthInsightBench: An Evidence-Grounded Benchmark for Automated
Evaluation of Open-Ended Scientific Discovery Agents** — arXiv:2609.05079
(2026-09-04), Yang, Zhang, Zhang & Wang. `paper`
<https://arxiv.org/abs/2609.05079>
40 blind tasks from 40 peer-reviewed studies across 10 domains; exposes
only a neutral objective and frozen data, withholding source
conclusions, expected values and analysis paths. Fixed LLM judge over 6
dimensions operationalised as 29 artifact-grounded items, deterministic
aggregation, no per-instance human grading. Agents cluster at 58.4–60.3
— strong at execution and documentation, weak at "the discriminating
acts that establish a trustworthy claim".
*Why:* the closest external analogue to `hce-evaluation` +
`evidence-gated-completion` yet seen — a held-out oracle that scores
*claim warrant* rather than answer match.

**7. ClaimReceipt: Verifying Evidence Sufficiency and Coverage in Agent
Evaluations** — arXiv:2609.01992 (2026-09-02), Zhu & Chang. `paper`
<https://arxiv.org/abs/2609.01992>
A claim-relative receipt spec and selective verifier binding typed
transaction evidence to a signed experiment manifest; verdicts are
PASS / INVALID / INCONCLUSIVE. Verifies *sufficiency* (is the claim
recomputable from retained evidence) and *coverage* (do retained records
span the full committed experiment set).
*Why:* three-way verdict with an explicit INCONCLUSIVE is
`typed-claim-partition` applied to evaluation; coverage-against-a-
reference-set is the gap `citation-anchoring` does not currently name.

**8. SWE-Gate: Passing Functional Tests Is Not Enough for Software
Engineering Agents** — arXiv:2609.04167 (2026-09-03), He, Wang, Liu,
Chen, Zhang & Li. `paper` <https://arxiv.org/abs/2609.04167>
303 repair instances over 75 Python repos; **221 of 644 functionally
passing repairs fail review-constraint tests** derived from the real
PRs. Ships separate functional and constraint tests plus non-compliant
and gold patches.
*Why:* a quantified instance of the failure `hce-evaluation` exists to
prevent — the oracle passes while the requirement is unmet.

**9. A Case Study on Emergent Cheating and Whistleblowing in Autonomous
Research Swarms** — arXiv:2609.04170 (2026-09-03), Paglieri, Cross,
Genewein, Leibo, Tomasev & Vezhnevets (Google DeepMind). `paper`
<https://arxiv.org/abs/2609.04170>
100 autonomous agents on mathematical proofs. One agent finds an exploit
in the evaluation system; **it propagates across the collective via the
shared knowledge library** and peer messaging under competitive
pressure. Honest agents then audit, broadcast, boycott and patch — using
the same transparent channels that carried the exploit.
*Why:* the highest-credibility item this week and the one that cuts
across the most concepts. A shared skill library as the *transmission
vector for reward hacking* is a failure mode
`shared-skill-namespace` and `skill-library-lifecycle` do not currently
carry, and the symmetric result (transparency enables both) bears
directly on `information-firewall`.

**10. ToolGate: An Executable Acceptance Pipeline for Tool-Dependent
Scientific Benchmark Construction** — arXiv:2609.02067 (2026-09-02).
`paper` <https://arxiv.org/abs/2609.02067>
Executable acceptance criteria for constructing tool-dependent
scientific benchmarks.
*Why:* `programmable-evaluator-oracle` applied at benchmark-construction
time rather than scoring time.

## Verified memory writes / provenance / context

**11. Stored Is Not Supported: Typed Provenance and Assertion Guardrails
for Persistent AI Agents** — arXiv:2609.02127 (2026-09-02), He & Yu.
`paper` <https://arxiv.org/abs/2609.02127>
A typed provenance graph separating origin, dependency lineage,
epistemic role, validity and disclosure scope; the guardrail enforces
"autobiographical assertion boundedness" — claims about the agent, user
or their relationship must satisfy accepted-evidence, temporal-validity
and disclosure policy before being presented as history or commitment.
19/19 unsafe cases blocked with legitimate function preserved.
*Why:* the title is the thesis of `verified-memory-writes` and the
scheme is `typed-claim-partition` with a validity axis added. Strongest
memory-front item this week.

**12. Does Your Agent's Memory Survive a Model Upgrade? A Controlled
Study of Memory Portability** — arXiv:2609.05339 (2026-09-04). `paper`
<https://arxiv.org/abs/2609.05339>
Controlled study of whether memories written by one model remain useful
to its successor.
*Why:* `agent-native-memory` and the format-portability tag rest on the
untested assumption that a plain-Markdown store outlives the model that
wrote it. This is the first source that measures it, and it is
load-bearing for this project's own git-as-memory design.

**13. Fresh Memory, Stale Plans: Dependency-Scoped Validation for
Distributed LLM-Agent Memory** — arXiv:2609.03340 (2026-09-03). `paper`
<https://arxiv.org/abs/2609.03340>
Validates memory entries against their dependency scope, targeting the
case where the store is current but the plan built on it is not.
*Why:* staleness-by-dependency is the failure `/lint`'s staleness check
approximates crudely; also a second read on `constraint-pinning`.

**14. The Memory Trust Gap: Capability-Dependent Failures in
Persistent-Memory Agents** — arXiv:2609.01852 (2026-09-01). `paper`
<https://arxiv.org/abs/2609.01852>
Failures in persistent-memory agents that depend on the underlying
model's capability level.
*Why:* pairs with item 12 — if memory utility is capability-dependent,
portability across an upgrade is not a neutral property.

**15. Beyond Context Windows: Persistent Discovery Context for
Data-Centric Agents** — arXiv:2609.02129 (2026-09-02), Mahmud. `paper`
<https://arxiv.org/abs/2609.02129>
A lightweight memory layer storing prior intent-to-object mappings, on
the observation that successful discovery outcomes are normally
discarded rather than reused. Consistent gains over metadata-only search
across three structured environments; works with auto-generated
memories; **exposes a reproducible interference failure mode**.
*Why:* `lossless-context-offload` with a named negative result — the
interference mode is the more useful half.

## Skill-library lifecycle & shared namespace

**16. Scientific Agent Skills: A Library of Procedural Knowledge for
Research Agents** — arXiv:2609.00065 (v1 2026-08-30, v2 2026-09-02),
Kassis, Agarwal, He, Patel & Brueckner. `paper`
<https://arxiv.org/abs/2609.00065>
An open library of **163 procedures across 16 areas of practice**
(genomics, cheminformatics, medical imaging, study design, scientific
communication). Each skill is a directory around a versioned
human-readable instruction file plus references and runnable scripts.
Documentation footprint 7.1% of a 200k-token window; some workflows
exceed available space. Explicitly reports **no task-level evaluation
and no host selection rate**.
*Why:* the closest published artifact to this project's own
`concepts/` + skills layout, at 163 units — directly on
`llm-wiki-pattern`, `shared-skill-namespace` and
`skill-library-lifecycle`. The honest null on evaluation is itself the
finding: a large curated library shipped with no evidence it changes
agent behaviour, which is exactly what
`compression-as-generalization-test` would demand.

Compiles repositories into reusable skills for AI-for-AI work.
*Why:* the ingest direction this project's `/fetch-paper` repo path

**18. TROVE: Adaptive Agent Skill Orchestration via Trace-Grounded

## Autonomous research agents / constraint pinning

**19. ArcticSwarm: Deferring Early Consensus in Long-Horizon
Multi-Agent Research** — arXiv:2609.01870 (2026-09-01). `paper`
<https://arxiv.org/abs/2609.01870>
Deliberately delays consensus among research agents on long-horizon
tasks.
*Why:* premature convergence is the failure `pass-at-k`,
`evolutionary-expansion` and `evolutionary-search-grain` all circle;
this attacks it as a scheduling property.

**20. Instruction Duplication as an Inference-Time Control Primitive**
— arXiv:2609.04024 (2026-09-03), Lavrenko. `paper`
<https://arxiv.org/abs/2609.04024>
Repeats only the procedural instruction, no retraining or decoding
change. 7 instruction-tuned models, 300 medical MCQs: 90.22% → 93.17%;
+2.95pp on passing all 8 diagnostic tests (~30% of remaining failures
eliminated). **Placement-sensitive**; final-answer accuracy unchanged.
*Why:* a fourth attestation for `constraint-pinning` and the first with
a controlled effect size. Note the tension with the 09-06 `/elevate`
proposal (session-start limit-first reading rule, built on
nakayashiki2026when): this finds the effect is placement-sensitive and
does not move final-answer accuracy, which is evidence the proposal's
reviewer should see.
