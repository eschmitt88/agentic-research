## 1. SkillOpt: Executive Strategy for Self-Evolving Agent Skills (v2)

- **URL:** https://arxiv.org/abs/2605.23904
- **Source:** arXiv (2605.23904)
- **Submitted:** v1 2026-05-22, v2 2026-05-25 (v2 in window)
- **Authors:** Yang, Gong, Huang, Yang, Zhou, Huang, Li, Gao, Dai, Liu, Qiu,
  Yang, Chen, Yang, Luo
- **Summary:** A text-space optimizer for agent skills: a separate optimizer
  model turns scored rollouts into bounded add/delete/replace edits on a
  single skill document, with learning-rate budgets and validation-based
  acceptance criteria. No inference-time overhead added. Tested across
  six benchmarks and three execution harnesses (direct chat, Codex,
  Claude Code) with seven target models. Reports +19.1 to +24.8 point
  gains on GPT-5.5. Optimized skills transfer across model scales and
  execution environments.
- **Why included:** The "tested across three execution harnesses" framing
  is the direct empirical claim that **skills are harness-portable** —
  which is the missing piece of `shared-skill-namespace`. If the same
  skill document yields gains under direct chat, Codex, AND Claude Code,
  the concept is no longer architecturally aspirational; it's measured.
  Also: bounded add/delete/replace edits with validation acceptance is
  itself a microcosm of `hce-evaluation` (search vs. accept-test
  separation) at the skill-document level.
- **Touches concepts:** `skill-library-lifecycle`, `shared-skill-namespace`,
  `scripted-tool-pipelines`, `hybrid-model-backends`, `hce-evaluation`,
  `pass-at-k`
- **Suggested action:** `/fetch-paper 2605.23904` — top priority.

## 2. A Comprehensive Survey on Agent Skills: Taxonomy, Techniques, and Applications (v3)

- **URL:** https://arxiv.org/abs/2605.07358
- **Source:** arXiv (2605.07358)
- **Submitted:** v1 2026-05-08, v2 2026-05-19, v3 2026-05-26 (v3 in window)
- **Authors:** Zhou, Shu, Su, Du, Fang, Lin
- **Summary:** Defines agent skills as "reusable procedural artifacts that
  coordinate tools, memory, and runtime context under task-specific
  constraints." Organizes the literature into four lifecycle stages:
  representation, acquisition, retrieval, evolution. Reviews methods,
  resources, applications. Discusses quality control, interoperability,
  safe updating, long-term capability management. Maintains a companion
  GitHub resource collection.
- **Why included:** Surveys exist to reify a sub-field's vocabulary. This
  one names the four-stage lifecycle (representation/acquisition/
  retrieval/evolution) that `skill-library-lifecycle` is currently
  describing in much fuzzier terms. Reading it likely renames or
  refactors `skill-library-lifecycle` to match canonical terminology.
  Also: the GitHub resource collection is a candidate prior-art map for
  the project's own concept index.
- **Touches concepts:** `skill-library-lifecycle`, `shared-skill-namespace`,
  `agent-native-memory`, `selective-memory-retrieval`,
  `context-eviction-policy`
- **Suggested action:** `/fetch-paper 2605.07358` — second priority after #1.

## 3. Reframing LLM Agent Security as an Agent–Human Interaction Problem

- **URL:** https://arxiv.org/abs/2605.24309
- **Source:** arXiv (2605.24309)
- **Submitted:** 2026-05-23 (pre-window by 2 days)
- **Authors:** Wang, Li, Tian
- **Summary:** Analyzes 59 academic papers, 21 production agent systems,
  and 26 security plugins as of April 2026. Core finding: industry
  deploys **human-centric mechanisms like policy specification and
  runtime approval** while academic research focuses on intent anchoring.
  Calls for treating Agent-Human Interaction (AHI) security as a primary
  research area with its own design principles and evaluation methods.
- **Why included:** This is the **fourth attestation
  `permission-gate-as-architecture`** has been waiting for, and the
  cleanest formulation of it yet. The prior wrap explicitly listed the
  3-of-4 attestations (Claude Code, OpenHarness, Bara's writeup) and
  flagged "one more attestation and it promotes." This paper provides
  it: a quantitative analysis showing industry deployment converges on
  runtime-approval / policy-specification as a primary mechanism, in
  contrast to academic research. Independent confirmation, with 21
  production systems backing the claim. Once fetched, the concept
  seed is ready to write.
- **Touches concepts:** `scripted-tool-pipelines`, `hierarchical-delegation`,
  `hybrid-model-backends`, `context-eviction-policy` (and seeds
  `permission-gate-as-architecture`)
- **Suggested action:** `/fetch-paper 2605.24309` — high priority.
  This is the unlock for the permission-gate concept.

## 4. HASP: Harnessing LLM Agents with Skill Programs

- **URL:** https://arxiv.org/abs/2605.17734
- **Source:** arXiv (2605.17734)
- **Submitted:** 2026-05-18 (pre-window — missed by 2026-05-25 digest)
- **Authors:** Liu, Ming, Joty, Zhao
- **Summary:** Converts reusable skills from past experiences into
  executable Program Functions (PFs). Rather than passive guidance, PFs
  act as "executable guardrails that activate on failure-prone states
  and modify the next action or inject corrective context." Sandboxing
  mechanism wraps candidates in a sandbox preamble with four sequential
  checks: syntax, interface, mock execution, return type. Applies at
  inference, post-training, or for self-improvement. Reports 25% gain
  on web-search reasoning vs. ReAct baseline.
- **Why included:** Two distinct contributions: (a) skills-as-executable-
  guardrails is a stronger framing than skills-as-prompts that
  `skill-library-lifecycle` currently uses — guardrails imply runtime
  enforcement, not just lookup. (b) The four-check sandbox preamble
  (syntax/interface/mock/return) is itself a `programmable-evaluator-
  oracle` mini-instance. The paper was submitted the same week as the
  2026-05-25 digest's window and was missed despite being directly
  on-thread.
- **Touches concepts:** `scripted-tool-pipelines`, `programmable-evaluator-oracle`,
  `skill-library-lifecycle`, `pass-at-k`, `hce-evaluation`
- **Suggested action:** `/fetch-paper 2605.17734`.
