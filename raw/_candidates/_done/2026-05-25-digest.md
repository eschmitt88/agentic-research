## 1. What Do Evolutionary Coding Agents Evolve?

- **URL:** https://arxiv.org/abs/2605.20086
- **Source:** arXiv (2605.20086)
- **Submitted:** 2026-05-19 (in window)
- **Authors:** Pelleriti, Nelaturu, Zhou, Li, Zimmer, Han, Pokutta
- **Summary:** Introduces `EvoTrace` (dataset of evolutionary coding traces
  across frameworks and tasks) and `EvoReplay` (methodology for
  reconstructing search states and intervening). Empirical finding:
  apparent benchmark gains in evolutionary coding agents arise from
  qualitatively different mechanisms, only some of which correspond to
  new algorithmic structure. Specifically, ~30% of "added lines" are
  recycled previously-deleted code; many gains come from constant
  re-tuning and recombining existing knowledge rather than novel
  structure; evaluators get overfit. Examining final scores alone masks
  the actual driving mechanism.
- **Why included:** Direct critical-methodology challenge to the entire
  evolutionary-search cluster the project has been seeding from. If the
  diagnostic holds, the project's reading of AlphaEvolve, FunSearch,
  CVEvolve, ToolMol, CodeEvolve should be tempered — final-metric deltas
  are not the right signal; the mechanism behind the delta is what's
  load-bearing. This also strengthens `hce-evaluation`'s case
  (search-time evaluator overfitting is exactly the failure mode HCE
  guards against).
- **Touches concepts:** `evolutionary-expansion`, `evolutionary-search-grain`,
  `programmable-evaluator-oracle`, `hce-evaluation`, `pass-at-k`,
  `citation-anchoring`
- **Suggested action:** `/fetch-paper 2605.20086` — top priority.

## 2. Rethinking How to Remember: Beyond Atomic Facts in Lifelong LLM Agent Memory (TriMem)

- **URL:** https://arxiv.org/abs/2605.19952
- **Source:** arXiv (2605.19952)
- **Submitted:** 2026-05-19 (in window)
- **Authors:** Sun, Zhu, Yao, Liu, Han
- **Summary:** Proposes `TriMem`, a memory system maintaining three
  coexisting representation granularities: (a) raw dialogue segments
  for storage fidelity, (b) extracted atomic facts for efficient
  retrieval, (c) synthesized profiles that aggregate dispersed facts
  into holistic semantic understanding for deep reasoning. Uses
  TextGrad-based prompt optimization to iteratively refine extraction
  and profiling prompts via response-quality feedback, achieving
  lifelong evolution without parameter updates. Evaluated on LoCoMo
  and PerLTQA.
- **Why included:** A second independent attestation (alongside H-Mem
  below) that the field is converging on **multi-granularity** memory
  representations rather than flat embeddings. This is the
  "what stays in the working set vs. what gets compressed" question
  that `context-eviction-policy` is trying to articulate. The
  granularity stack (raw / atomic / synthesized) is itself a candidate
  concept seed if a third attestation appears.
- **Touches concepts:** `agent-native-memory`, `selective-memory-retrieval`,
  `context-eviction-policy`, `skill-library-lifecycle`
- **Suggested action:** `/fetch-paper 2605.19952`.

## 3. APEX: Autonomous Policy Exploration for Self-Evolving LLM Agents

- **URL:** https://arxiv.org/abs/2605.21240
- **Source:** arXiv (2605.21240)
- **Submitted:** 2026-05-20 (in window)
- **Authors:** Li, Yang, Zheng, Hu, Sui, Wang, He, Hooi
- **Summary:** Names a failure mode — "exploration collapse" — where
  self-evolving agents converge on familiar high-reward routines and
  stop exploring. APEX maintains an explicit *strategy space as a DAG*,
  uses `Fork Discovery` to expand exploration paths and `Policy Selection`
  to balance exploration/exploitation. Tested on text-adventure and web
  interaction tasks.
- **Why included:** "Exploration collapse" is a precise name for a
  pathology that intersects `evolutionary-search-grain` (the search
  *operator set* matters because narrow operators collapse to local
  optima) and AIRA2's "loop overfits to its own evaluation signal"
  bottleneck. The DAG-of-strategies framing is also a candidate dual to
  the lineage-aware sampling in CVEvolve. Worth reading alongside #1 —
  both critique what "self-improvement" actually produces.
- **Touches concepts:** `evolutionary-expansion`, `evolutionary-search-grain`,
  `hce-evaluation`, `pass-at-k`
- **Suggested action:** `/fetch-paper 2605.21240`.

## 5. Agentic Discovery of Neural Architectures: AIRA-Compose and AIRA-Design

- **URL:** https://arxiv.org/abs/2605.15871
- **Source:** arXiv (2605.15871)
- **Submitted:** 2026-05-15 (pre-window — missed by prior digest)
- **Authors:** Pepe, Lin, Magka, Acun, Wu, Protopopov, Wu, Bachrach
- **Summary:** Two complementary frameworks for LLM agents to autonomously
  design foundation-model architectures beyond standard Transformers.
  `AIRA-Compose` targets high-level architecture exploration;
  `AIRA-Design` targets low-level implementation. Reports
  agent-discovered architectures beating Llama 3.2 baselines, with some
  variants scaling faster. Framed as a step toward "recursive
  self-improvement" through autonomous discovery of both architectural
  designs and algorithmic optimizations.
- **Why included:** First AIRA-family paper since AIRA_2 (2603.26499)
  that explicitly extends the agent's *search target* from solutions to
  architectures themselves. The Compose/Design split is its own design
  axis (high-level architecture vs. low-level implementation as separate
  agent loops) that could seed a new concept. Strong AIRA-cluster
  alignment.
- **Touches concepts:** `evolutionary-expansion`, `evolutionary-search-grain`,
  `hierarchical-delegation`, `pass-at-k`
- **Suggested action:** `/fetch-paper 2605.15871`.

## 7. PARNESS: A Paper Harness for End-to-End Automated Scientific Research

- **URL:** https://arxiv.org/abs/2605.05258
- **Source:** arXiv (2605.05258)
- **Submitted:** 2026-05-06 (well pre-window — missed by both prior digests)
- **Authors:** Wang, Luan
- **Summary:** A "paper harness" framework for end-to-end automated
  scientific research. Key innovations: (a) a thin DAG kernel with a
  four-field Agent contract so workflows are expressed as user-editable
  YAML; (b) full-text PDF indexing of paper bodies, figures, tables
  (beyond abstracts); (c) a knowledge graph retrieving papers, ideas,
  experiments, and code through scenario-typed queries; (d) integration
  points letting modern coding agents extend or replace framework
  components. Includes an example end-to-end generated paper in the
  appendix.
- **Why included:** This is the closest external analogue to *this
  project's own architecture*. The "DAG kernel + YAML workflows +
  knowledge graph + scenario-typed queries + integration with coding
  agents" stack is exactly what agentic-research is doing with skills +
  concepts + literature + experiments. Reading it would surface either
  validation of current design or counter-design points worth
  borrowing. Flagging now because the prior digests both missed it
  despite the title containing the word "harness."
- **Touches concepts:** `scripted-tool-pipelines`, `web-grounded-literature`,
