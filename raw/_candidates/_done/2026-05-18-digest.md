## 1. CVEvolve: Autonomous Algorithm Discovery for Unstructured Scientific Data Processing

- **URL:** https://arxiv.org/abs/2605.11359
- **Source:** arXiv (2605.11359)
- **Submitted:** 2026-05-14 (in window)
- **Summary:** Autonomous search controller wraps an LLM agent that can use
  code/data/evaluation/history/visualization tools. Each round picks one of
  three actions — `generate` (new algorithms), `tune` (improve existing),
  `evolve` (hybridize existing) — and uses lineage-aware stochastic
  candidate sampling. Designed for unstructured scientific data (CV-style
  pipelines) rather than the closed-form benchmarks that AlphaEvolve and
  FunSearch target.
- **Why included:** This is the cleanest articulation I've seen of an
  evolutionary search whose *operator set is typed and small* (three
  named actions). That maps directly onto `evolutionary-expansion` and
  `evolutionary-search-grain` as a concrete design point. The
  "lineage-aware stochastic sampling" is also a candidate concept for
  selection policy across cycles.
- **Touches concepts:** `evolutionary-expansion`, `evolutionary-search-grain`,
  `programmable-evaluator-oracle`
- **Suggested action:** `/fetch-paper 2605.11359` — highest priority in
  this batch.

## 2. Evolutionary Task Discovery: Advancing Reasoning Frontiers via Skill Composition and Complexity Scaling

- **URL:** https://arxiv.org/abs/2605.11666
- **Source:** arXiv (2605.11666)
- **Submitted:** 2026-05-14 (in window)
- **Summary:** Generates new training tasks by *composing existing skills*
  and scaling task complexity, then uses the generated tasks to push
  reasoning performance. The skill-composition operator is itself the
  search primitive.
- **Why included:** Inverts the usual framing — instead of acquiring
  skills to solve fixed tasks, it *generates tasks from skills*. Directly
  intersects `skill-library-lifecycle` (skills become a generative
  vocabulary, not just a lookup table) and `evolutionary-expansion`
  (tasks themselves are the population being evolved).
- **Touches concepts:** `skill-library-lifecycle`, `evolutionary-expansion`,
  `evolutionary-search-grain`
- **Suggested action:** `/fetch-paper 2605.11666`.

## 3. ComplexMCP: Evaluation of LLM Agents in Dynamic, Interdependent, and Large-Scale Tool Sandbox

- **URL:** https://arxiv.org/abs/2605.10787
- **Source:** arXiv (2605.10787)
- **Submitted:** 2026-05-11 (window boundary)
- **Summary:** Benchmark built on MCP with 300+ systematically validated
  tools across 7 stateful sandboxes. Targets *interdependent* tool
  use (one tool's effect changes another's behavior) and *large-scale*
  tool surfaces — the regime where the "expose-all-tools-in-context"
  pattern collapses.
- **Why included:** Empirical counterpart to the harness-architecture
  cluster's concern with tool-surface scaling. The 7-sandbox, 300+ tool
  setup is the right scale to actually stress `selective-memory-retrieval`,
  `context-eviction-policy`, and the tool-surface-vs-skills tradeoff that
  `scripted-tool-pipelines` describes. Could serve as an external yardstick.
- **Touches concepts:** `scripted-tool-pipelines`, `context-eviction-policy`,
  `selective-memory-retrieval`, `shared-skill-namespace`
- **Suggested action:** `/fetch-paper 2605.10787`.

## 4. Iterative Audit Convergence in LLM-Managed Multi-Agent Systems

- **URL:** https://arxiv.org/abs/2605.12280
- **Source:** arXiv (2605.12280)
- **Submitted:** 2026-05-12 (in window)
- **Summary:** Case study of agent-driven iterative auditing applied to
  AEGIS, a production seven-lane orchestration pipeline with a
  ~7150-line prompt-specification surface. Reports convergence dynamics
  of the audit loop over many cycles.
- **Why included:** Two angles. (a) The "prompt-specification surface"
  framing — treating prompts as a typed artifact subject to QA — is a
  direct cousin of `typed-claim-partition` and `citation-anchoring`
  applied to prompts rather than outputs. (b) Convergence dynamics of
  an audit loop are the read-side analogue of `hce-evaluation`: how
  does an autonomous loop avoid certifying its own drift?
- **Touches concepts:** `hce-evaluation`, `typed-claim-partition`,
  `hierarchical-delegation`
- **Suggested action:** Skim abstract first; `/fetch-paper 2605.12280`

## 5. Dive into Claude Code: The Design Space of Today's and Future AI Agent Systems

- **URL:** https://arxiv.org/abs/2604.14228
- **Repo:** https://github.com/VILA-Lab/Dive-into-Claude-Code
- **Source:** arXiv (2604.14228) — **pre-window** (April 2026)
- **Why pre-window item included:** NOTES.md (2026-05-15 wrap) flagged
  this as a likely fourth-attestation source for promoting
  `permission-gate-as-architecture` from candidate to concept. Did not
  surface in prior digests — pre-dates the agent-harnesses discover
  pass that found the Paddo leak post and Hermes repo.
- **Summary:** Reverse-engineering of Claude Code v2.1.88 by VILA-Lab
  (Liu, Zhao, Shang, Shen). Central quantitative finding: **98.4% of
  the codebase is deterministic infrastructure** across 5 layers, 7
  safety systems, and 54 tools; only 1.6% is AI decision logic. Names
  seven components: a permission system with seven modes and an
  ML-based classifier, a five-layer compaction pipeline, four
  extensibility mechanisms (MCP/plugins/skills/hooks), a subagent
  delegation/orchestration mechanism, and append-oriented session
  storage. Uses a values → principles → implementation analytical
  framework with OpenClaw as the comparison baseline.
- **Why included:** Three independent reasons. (a) The permission
  system is explicitly framed as one of seven first-class components
  with seven modes plus an ML classifier — this is the missing fourth
  attestation for `permission-gate-as-architecture`. (b) The 98.4%
  infrastructure / 1.6% AI-logic split is a hard quantitative claim
  that grounds the project's working assumption that *harness
  engineering, not model choice, is the locus of agent capability*.
  (c) The five-layer compaction pipeline gives `context-eviction-policy`
  a concrete reference implementation to point at.
- **Touches concepts:** `context-eviction-policy`,
  `hierarchical-delegation`, `shared-skill-namespace`,
  `scripted-tool-pipelines`, (candidate)
  `permission-gate-as-architecture`
- **Suggested action:** `/fetch-paper 2604.14228` — likely highest
  *strategic* priority across the whole batch despite being pre-window.

- **Why pre-window item included:** NOTES.md (2026-05-15 wrap) flagged

  treat the repo as still active, and the official site
  (claw-code.codes) describes the project in present tense. The DMCA
  risk appears to have receded.
- **Summary:** Clean-room reimplementation of Claude Code's
  architectural patterns by Sigrid Jin, triggered by the March-2026
  source-map leak. ~73% Rust (conversation loop, tool execution,
  streaming) and ~27% Python (LLM provider abstraction, lifecycle,
  session persistence). Trait-based `ConversationRuntime<C, T>`
  decouples API client from tool execution. Hit 100K stars in 24
  hours after the leak. Independent code audits report no Anthropic
  proprietary source, no model weights, no API keys.
- **Why included:** Most architecturally substantive open-source
  parallel to Claude Code. The Rust-core / Python-edge split is a
  substrate choice this project's harness-architecture cluster
  has not yet seen attested anywhere else — Hermes is pure Python,
  OpenHarness is pure Python, Claude Code is pure TypeScript.
  Reading the permission system here would be the fourth
  attestation if VILA-Lab paper is hard to access, and provides
  the alternate-substrate datum for whether harness patterns are
  language-independent.
