# Digest candidates — 2026-07-06

Active fronts (from concepts/ + last NOTES): autonomous ML/scientific-research
agents (dominant), agent memory & multi-granularity retrieval, permission-gate
governance, skill-library lifecycle, evolutionary / evaluator-guided search
with hidden-consistent evaluation.

## Honest evaluation & research-loop overfitting (HCE front)

1. **Closed-loop Auto Research for Molecular Property Prediction: Discovering and Certifying Generalizable Improvements** — system + methodology
   - https://arxiv.org/abs/2606.22731 · arXiv late Jun 2026
   - A closed-loop autonomous research system whose headline contribution is
     the *certification* step: research actions are evaluated inside the
     loop, then the system asks which improvements transfer to held-out
     evidence — attribution and certification across intervention classes
     rather than only optimization within one. This is the same
     search-signal/selection-signal decoupling that `hce-evaluation` encodes
     (AIRA2's bottleneck framing), instantiated in a chemistry domain, which
     would give the concept a cross-domain attestation.
   - reason: strongest in-window hit; directly sharpens `hce-evaluation`
     with a "certify generalizable improvements" mechanism beyond
     split-hygiene.

2. **What Fits (Into Few Tokens) Doesn't Overfit: Compression and Generalization in ML Research Agents** — analysis
   - https://arxiv.org/abs/2606.11045 · arXiv mid Jun 2026 (older slip,
     included for core-theme fit)
   - Places an explicit information bottleneck between an *explorer* (which
     searches adaptively using the validation set) and a *reproducer* (which
     receives only a short prompt plus training data). If the reproducer
     matches the explorer, the validation-dependent strategy fit through the
     compressed prompt — an operational test ("output compression") of
     whether an ML-research agent's gains are generalizable or
     validation-overfit. Novel mechanism adjacent to `hce-evaluation` and
     `pass-at-k`; potentially a new concept (compression-as-generalization
     -test).
   - reason: core-theme (loop-overfitting) method with a falsifiable
     protocol; the kind of evidence `/elevate` wants for HCE tooling.

## Agent memory (multi-granularity / consolidation)

3. **Are We Ready For An Agent-Native Memory System?** — position paper
   - https://arxiv.org/abs/2606.24775 · arXiv late Jun 2026 (Zhou et al.,
     Shanghai Jiao Tong)
   - Position paper arguing the field's memory systems are retrofitted
     RAG/conversation stores rather than designed for agents' actual
     read/write workloads; surveys what an agent-native design would
     require. Title-level match for the existing `agent-native-memory`
     concept — likely either a direct attestation or a useful counterpoint
     to its current framing.
   - reason: direct concept anchor; cheap high-value ingest for the memory
     cluster.

4. **TRUSTMEM: Learning Trustworthy Memory Consolidation for LLM Agents with Long-Term Memory** — method
   - https://arxiv.org/abs/2606.25161 · arXiv late Jun 2026
   - Learns *when to trust* consolidation: write-validation and
     conflict-aware merging so that consolidated long-term memory doesn't
     silently absorb errors. Attests the consolidation/write-policy edge
     shared by `multi-granularity-memory` and `skill-library-lifecycle`
     (what gets promoted into the durable store, and on what evidence).
   - reason: fills the "consolidation trust" gap the memory cluster
     currently covers only via retrieval-side gating
     (`selective-memory-retrieval`).

## Permission-gate & governance architecture

5. **A Deterministic Control Plane for LLM Coding Agents** — system
   - https://arxiv.org/abs/2606.26924 · arXiv late Jun 2026
   - Argues LLM-based governors ("governing the governor") and rule-based
     guardrails both fail, and builds a deterministic control plane that
     enforces policy over agent actions at the execution layer. Directly on
     `permission-gate-as-architecture`'s claim that the approval layer is a
     first-class architectural component, with a determinism argument the
     concept currently lacks.
   - reason: strongest governance hit; adds the deterministic-vs-LLM-judge
     axis to the permission-gate concept.

6. **AgenticOS: An Intent-Oriented Secure Operating System Architecture for Autonomous AI Agents** — system/architecture
   - https://arxiv.org/abs/2606.21129 · arXiv late Jun 2026
   - Four-layer OS-style architecture (Ghost Kernel, Logic Shutter, Agent
     Capsule, Semantic Boundary Gateway) with admission control: agents
     that pass admission get stricter runtime monitoring, resource budgets,
     and output auditing. Bridges `permission-gate-as-architecture` and
     `budget-as-ceiling` (budgets as an admission/runtime primitive, not
     just a halting condition).
   - reason: architectural attestation linking two governance concepts.

7. **DEMM-Bench: A Cross-Regime Benchmark for Agent-Runtime Governance-Evidence Sufficiency** — benchmark
   - https://arxiv.org/abs/2606.20634 · arXiv late Jun 2026
   - Benchmarks whether the *evidence* available to a runtime governor is
     sufficient to decide gating across regimes — i.e., measures the
     information side of the permission gate rather than the mechanism.
     Evaluation-shaped complement to items 5–6.
   - reason: first benchmark seen for governance-gating decisions; useful
     empirical anchor if the governance cluster grows toward a MoC.
